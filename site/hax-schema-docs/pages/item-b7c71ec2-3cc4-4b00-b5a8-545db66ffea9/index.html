While haxProperties describes how an element appears in the gizmo browser and how HAX configures it via settings forms, haxHooks lets an element participate in HAX lifecycle / state changes without importing HAX. This keeps elements decoupled from the editor: an element opts into deeper integration by declaring a haxHooks() method that maps hook names to method names on the element.

The HAX store discovers these via testHook / runHook and invokes them at the right lifecycle moment. The callback name is your choice; the convention is hax + the hook name.

Available hooks

  • activeElementChanged — input (activeElement, value) where value is whether the element is active. See @haxtheweb/retro-card/retro-card.js
  • editModeChanged — input (value) where value is the edit-mode state of the body. See @haxtheweb/retro-card/retro-card.js
  • inlineContextMenu — allows dynamically adding buttons to the editor context menu. See @haxtheweb/multiple-choice/multiple-choice.js
  • gizmoRegistration — lets an element rewrite the store when it is registered with HAX (e.g. register a custom app, extend validGizmoTypes). See @haxtheweb/github-preview/github-preview.js
  • preProcessNodeToContent — input (node), the item about to be converted to content for export. See @haxtheweb/editable-table/editable-table.js
  • progressiveEnhancement — works on the element ONLY in the slotted / innerHTML area; must return content. See @haxtheweb/meme-maker/meme-maker.js
  • postProcessNodeToContent — input (content), an HTML blob about to be returned for export. See @haxtheweb/video-player/video-player.js
  • preProcessInsertContent — input (node), the item about to be inserted into the content. See @haxtheweb/multiple-choice/multiple-choice.js
  • siteToSkeleton — input (details) where details is { uuidMap, direction }; element rewrites its own site-item UUID references so skeleton structure and content stay in sync. See @haxtheweb/haxcms-elements/lib/ui-components/magic/site-collection-list.js
  • mediaSourceUpdated — input (path, store) where path is the clean URL of a file just modified in place and store is the HAXStore instance. See @haxtheweb/media-image/media-image.js
  • processFileUpload — input (values, response, store) invoked from the generic tray upload / drag-drop path after a file is uploaded but before insertion. Return false to decline, or a mapping object to run a post-upload transform. See @haxtheweb/slide-deck/slide-deck.js

The authoritative source for the hook list is the comment block at the top of HAXWiring.js.
